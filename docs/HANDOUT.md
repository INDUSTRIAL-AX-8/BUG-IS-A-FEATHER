# 검토 핸드아웃 — 데이터의 적절성과 모델의 정합성

- 검토 대상: `main` `887ed43` (2026-11-27, PR #2 병합 전 기준)
- 방법: 코드 열람, 백엔드 테스트 실행, 데모 데이터 2종(사출기 3호 / 합성 시나리오)을 넣고 API·화면에서 수치를 직접 확인
- 확인하지 못한 것: KAMP 실데이터(원본이 저장소에 없음), Ollama 실제 답변, PostgreSQL

한 줄 결론: **계산 로직은 테스트로 고정되어 있고 화면 간 수치도 대체로 맞는다. 다만 지금 데모 데이터는 "엔진이 돈다"는 것만 보여 주고
"현장에서 맞는다"는 것은 보여 주지 못한다.** 발표·시연에서 아래 1~4번을 먼저 알고 설명하는 것이 안전하다.

> 갱신: 권장 조치 1번(시연 기록 구분)과 2번(기준 구간)은 반영했다. 해당 항목에 **[반영됨]** 으로 표시하고 바뀐 수치를 적었다.
> 아래 본문의 수치는 반영 전(`887ed43`) 기준이다.

## 1. 데이터의 적절성

| 데이터 | 규모 | 성격 | 이 데이터로 말할 수 있는 것 |
|---|---|---|---|
| 사출기 3호 (`samples/injection_m3`) | 3일, 1시간 1행, 23행 + 정지 1행. 생산 6,785개, 불량 277개(4.1%) | 문제 02 의 **가상 자료**. 답(금형 온도)이 들어 있음 | 엔진이 심어진 답을 찾는다 (동작 확인) |
| 합성 시나리오 (`seed-sample`, 시드 42) | LOT 734, 완제품 480, 측정 3,103, 불량 판정 33건(6.9%) | 생성기가 원인(원자재 LOT, 설비)을 심음 | 심은 원인이 Top-3 에 든다 (통합 테스트) |
| KAMP 다이캐스팅 | shot 5,161, 판정 1,144 (README 기준) | 실데이터. **원본 미포함**, 시각은 가상 | 이번 검토에서 재현하지 못함 (테스트 1건 건너뜀) |

확인된 문제:

1. **실데이터 검증이 없다.** 저장소에서 바로 돌릴 수 있는 두 데이터는 모두 답을 알고 만든 자료다. 엔진이 답을 맞히는 것은
   정확도의 증거가 아니라 동작 확인이다. KAMP 실데이터 결과("보고서 수치와 동일")는 원본이 있어야 확인된다.
2. **표본이 작다.** 사출기 3호는 23행이다. 요인 분석은 8행부터 돌고(`driver_analysis.min_rows`), "같은 금형 온도에서 작업자 비교"는
   기술자 1행 대 신입 4행이다. 결론 문장은 맞게 나오지만 근거 행 수를 같이 말해야 한다.
3. **실시간 수집(시연)이 만든 가짜 기록이 실제 테이블에 섞인다.** LOT 번호 규칙이 같고(`IM3-YYYYMMDD-HHMM`) 구분 컬럼이 없다.
   3600배속으로 10초쯤 돌린 뒤 LOT 73개 중 44개가 시연 기록이었고 날짜는 미래(11-28, 11-29)였다. 이후의 SPC·요인 분석·생산 대시보드가
   이 기록을 실제 기록과 함께 쓴다. 실무자 권한이면 켤 수 있다.
   **[반영됨]** 시연 기록에 표시(`is_simulated`)를 두어 목록에 '시연'으로 보이고, 관리자가 한 번에 지울 수 있으며, 운영 서버에서는
   설정으로 끌 수 있다. 분석에서 자동으로 빼지는 않는다(시연 화면이 그 수치를 보여 줘야 하므로) — 시연 뒤에는 지우고 분석한다.
4. **정보 손실.** 집계 기록은 시간당 판정 1건에 "가장 많았던 불량 유형" 하나만 남는다(메모에 표시). 유형별 분석은 약한 근거로만 써야 한다.
5. **LOT 상태 규칙이 경로마다 다르다.** 화면에서 불량을 등록하면 LOT 상태가 "불량"이 되지만, 공정 기록 가져오기로 들어온 판정은
   전량 불량일 때만 "불량"이 된다(코드 주석에만 있고 화면·README 에는 없다). 같은 "정상" 표시가 "불량 0개"와 "일부 불량"을 함께 뜻한다.

## 2. 모델의 정합성

### 2.1 관리도(SPC) — 기준선이 이상 구간을 포함한다

넬슨룰 판정 자체는 룰별 위반/비위반 단위 테스트 24개로 고정되어 있다. 문제는 **기준선**이다.

- 사출기 3호 데이터에는 고정된 기준 구간이 없어 "처음 20개 점"으로 임시 한계를 만든다. 금형 온도는 6번째 점부터 오르기 시작하므로
  이상 구간이 기준선에 들어간다.
- 결과: 금형 온도 중심선 57.15℃, 관리한계 52.95 ~ 61.35℃. **정상 운전값 51℃가 하한 이탈**이 되고, 23개 점 전부가 어떤 룰이든 위반이다
  (수지 온도는 23점 중 15점).
- 대시보드의 "미확인 SPC 위반 16건"은 이 한계에서 나온 숫자다. 예측(ARIMA)의 위험 점수와 원인 점수의 SPC 요소도 같은 한계를 쓴다.
- 조치: 가져오기 때 안정 구간(예: 03-04 08:00~12:00)을 기준선으로 고정하거나, 화면에 "임시 한계 — 기준 구간 미지정"을 더 크게 표시한다.
  23점으로는 표준 권장(안정 구간 20개 이상)을 채울 수 없다는 점도 같이 알려야 한다.

**[반영됨]** 매핑 파일에 기준 구간(`baseline`)을 적으면 가져올 때 그 구간으로 한계를 고정한다. 사출기 3호는 정비 뒤 불량률이 1.0% 로
회복된 03-06 10~15시(6행)를 금형 온도의 기준으로 삼았다.

| 금형 온도 | 반영 전 (임시 한계) | 반영 후 (기준 구간 고정) |
|---|---|---|
| 중심선 / 한계 | 57.15 / 52.95 ~ 61.35℃ | 51.33 / 49.74 ~ 52.93℃ |
| 정상 운전값 51℃ | 하한 이탈 | 위반 아님 |
| 첫 한계 이탈 | 첫 점(03-04 08:00, 51℃) | 03-04 12:00 (53℃, 오르기 시작한 시점) |
| 룰에 걸린 점 | 23점 전부 | 15점 (03-04 11시 ~ 03-06 10시) |

남는 한계:

- 기준 구간이 6행이라 권장(20행)에 못 미친다. 화면에 그 안내가 뜬다. 한계 폭은 데이터가 쌓이면 다시 고정해야 한다.
- 수지 온도는 1℃ 단위 기록이라 안정 구간의 산포가 0 에 가까워 기준 구간을 정하지 않았다. 임시 한계로 남고, **임시 한계의 위반은
  경보로 세지 않는다**(대시보드 건수에서 제외, 목록에 '임시' 표시, 실시간 수집의 불량 의심으로도 올리지 않음).
  대시보드 "미확인 SPC 위반"은 16건 → 5건(금형 온도)으로 바뀌고, 수지 온도의 임시 한계 위반 7건은 제외로 표시된다.
- 연속 룰(R2 등)은 정비 정지를 넘어 이어서 센다. 정비 직후 첫 점(03-06 10:00, 52℃)이 R2·R6 에 걸리는 것은 이 때문이다.

### 2.2 요인 분석 — 결론은 타당하나 유의확률이 낙관적이다

- 준이항 로지스틱(과산포 보정) → 전진 선택 → 같은 조건 층에서 교란 확인 순서는 합리적이고, 금형 온도·사출 압력·냉각 시간·작업자가
  함께 움직인 자료에서 "다른 요인으로 설명됨"을 구분해 낸다.
- 23행에서 요인을 고른 뒤 같은 자료로 낸 p 값(`p<0.001`)은 선택 편향이 있어 실제보다 작다. 확신도 "높음" 표시는 행 수와 함께 보여야 한다.
- **학습 경계가 순환한다.** "금형 온도 ≤ 57℃"는 이 불량 자료에서 배운 값이고, 이 값이 다시 원인 점수의 조건 이탈·공유 불량률,
  생산 대시보드의 "불량 원인 Top", 실시간 수집의 경보 기준으로 쓰인다. 요인 분석·이력 추적·생산 대시보드가 모두 금형 온도를 1순위로
  보여 주지만 **독립된 세 근거가 아니라 한 근거의 세 표현**이다.

### 2.3 원인 후보 점수 — 같은 질문에 모듈마다 다른 통계를 쓴다

- 점수는 6개 요소의 가중 평균이고 요소별 근거 문장이 나온다(설명 가능). 가중치(1.0 / 1.5 / 0.5 / 1.0 / 0.8 / 1.2)는 사람이 정한 값이며
  데이터로 학습되지 않는다. "쌓일수록 정확해진다"는 것은 (f) 과거 확정 이력 요소 하나를 통해서만 일어난다.
- 사출기 3호의 금형 온도 점수 0.417 은 공유 불량률(1.5) + 조건 이탈(1.0) 을 가중치 합 6.0 으로 나눈 값이다. 나머지 후보는 0.000 이다.
- 공유 불량률의 근거는 "거친 제품 182/2,031개 불량 vs 거치지 않은 제품 68/4,454개, **p = 5.8e-43**"로 나온다. 이 값은 6,485개 제품을
  서로 독립인 것처럼 센 Fisher 검정이다. 실제 관측 단위는 22개 시간 구간이고, 같은 자료에 요인 분석은 과산포를 보정한다.
  **두 모듈이 같은 질문에 다른 가정으로 답하고 있고, 점수 쪽 p 값은 크게 과장되어 있다.**
- 화면 머리말의 "완제품 22 중 불량 22"는 LOT(시간 구간) 단위, 근거 문장은 제품 수량 단위다. 단위가 섞여 보이므로 표기를 맞춰야 한다.
- 공정·설비 노드는 모든 제품이 거쳐 비교군이 없고 "공통 경로 감쇠"로 0 점이 된다. 단일 라인 자료에서는 조건 노드만 점수를 받는 구조다.

### 2.4 추세 예측(ARIMA)

- 합성 시나리오에서는 심어 둔 추세(원자재-B 수분)가 위험 점수 1.0 으로 1위, 나머지는 0.19 이하로 구분된다.
- 사출기 3호는 23점이라 최소 30점에 못 미쳐 예측이 없다. 기본 Docker 데모에서 "주의 부품" 칸은 비어 있다.
- 위험 점수는 정규분포 가정으로 관리한계·규격 밖 확률을 계산한다. 관리한계가 2.1 처럼 오염되면 위험 점수도 같이 틀어진다.

### 2.5 정확도 지표(Top-k)

- 합성 시나리오: 확정 21건 기준 Top-1 81%, Top-3 86%, Top-5 95%. 주별 표본은 8건, 3건, 10건이다.
- 이 수치는 낙관적이다. 확정 이력은 생성기가 심어 둔 정답으로 만들고, 원인을 심지 않은 불량 12건은 확정이 없어 분모에서 빠진다.
- 실사용에서도 구조적 편향이 있다. 실무자는 후보 순위를 본 뒤 원인을 확정하고, 확정된 원인은 (f) 요소로 다음 순위를 올린다.
  정확도가 오르는 것이 "모델이 좋아져서"인지 "모델이 고른 것을 사람이 따라가서"인지 이 지표만으로는 구분할 수 없다.

## 3. 권장 조치 (우선순위 순)

1. **[반영됨]** 실시간 수집 기록에 구분 표시를 두거나 별도 DB 에서만 돌게 한다. 운영 DB 에서는 꺼 둔다.
2. **[반영됨]** 데모 데이터 가져오기에 안정 구간 기준선 고정을 넣는다. 임시 한계일 때는 위반 건수를 경보로 세지 않는다.
3. 원인 점수의 Fisher 검정을 관측 단위(시간 구간·LOT)로 맞추거나, 근거 문장에서 p 값을 빼고 불량률 차이만 보여 준다.
4. 결론·확신도 옆에 근거 행 수를 항상 표시한다 (예: "23행 기준", "기술자 1행 vs 신입 4행").
5. 실데이터(KAMP 또는 현장 기록)로 "학습 구간과 평가 구간을 나눠" 원인 순위를 검증하고, 그 결과를 README 에 적는다.
6. 정확도 지표에 "확정 없는 판정 수"와 "순위를 보기 전에 확정한 건"을 구분할 방법을 둔다.
