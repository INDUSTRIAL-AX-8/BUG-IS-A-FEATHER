# BUG-IS-A-FEATHER — 계보 기반 불량 원인 추적 시스템

사내망(폐쇄망) 단일 서버에서 동작하는 범용 불량 원인 추적 도구입니다.
제품 계보(DAG)를 거슬러 원인 후보를 찾고, 넬슨룰 SPC, ARIMA 추세 예측, 불량 판정 피드백,
로컬 LLM 어시스턴트를 한 흐름으로 제공합니다. 런타임에 외부 인터넷 호출이 없습니다.

- 명세: [SPEC_불량원인추적.md](SPEC_불량원인추적.md)
- 설계: [docs/DESIGN.md](docs/DESIGN.md)
- 검토 핸드아웃(데이터의 적절성·모델의 정합성): [docs/HANDOUT.md](docs/HANDOUT.md)

## 가장 쉬운 실행 (Windows)

1. **`set_up.bat`** 더블클릭 — 처음 한 번만. Python 가상환경·패키지 설치, 설정 파일 생성, 화면 빌드, DB 준비, 데모 데이터 선택
   (1 사출기 3호 / 2 합성 시나리오 / 3 KAMP 실데이터 / 4 건너뛰기). `offline_bundle\wheels` 가 있으면 인터넷 없이 설치합니다.
2. **`run.bat`** 더블클릭 — 코드가 업데이트됐으면 DB 를 자동으로 맞춘 뒤 서버가 켜지고 브라우저가 `http://localhost:8000` 을 엽니다. 끄려면 창에서 Ctrl+C. 다른 포트는 `run.bat 8080`.

필요한 것: Python 3.12 이상(3.13 권장, 설치 시 "Add python.exe to PATH" 체크), 화면 빌드용 Node.js 20 이상(빌드된 `frontend\dist` 를 복사해 오면 불필요).

## SPC 동작 요약

- 관리도 종류: 서브그룹 크기 1 → I-MR, 2~9 → Xbar-R, 10 이상 → Xbar-S (특성별 수동 지정 가능)
- 관리한계: 관리자가 **기준 구간**을 지정해 계산·고정(버전 관리, AuditLog). 고정 전에는 처음 20개 서브그룹으로 계산한 *임시 한계*를 쓴다.
- 넬슨룰: 전역 기본값(`설정 > nelson_rules`) + 특성별 덮어쓰기. 룰 8 은 넬슨 원 정의대로 "±1σ 밖 연속 n점이 중심선 양쪽에 걸침" 으로 판정한다.
- 같은 룰이 이어서 성립하면 하나의 위반으로 묶고, 처음 성립한 시점을 발생 시각으로 저장한다. 확인(ack)한 위반은 재계산해도 유지된다.
- 스케줄러가 주기적으로(기본 60분) 위반을 재계산한다.

## 원인 후보 점수 (설명 가능)

불량 LOT 의 상위 계보(LOT, 공정, 설비, 조건 노드) 각각에 대해 6개 요소를 0~1 로 계산하고,
`설정 > cause_weights` 가중치로 가중 평균합니다. 화면에서 요소별 기여도 막대와 근거 문장을 보여줍니다.

| 요소 | 계산 |
|---|---|
| (a) SPC 신호 | 노드 관련 특성값의 넬슨룰 위반 룰 종류 수 (LOT: 그 LOT 포함 위반, 설비: ±N일 처리 LOT 포함 위반, 공정: 그 공정 특성 위반) |
| (b) 공유 불량률 | 노드를 거친 완제품 vs 거치지 않은 완제품 불량률. Beta(α,β) 평활 Lift + Fisher 정확 검정 p-value |
| (c) ARIMA 위험 | 관련 특성의 최신 예측 위험 점수 |
| (d) 작업 조건 이탈 | 추적 경로 run 중 허용 범위를 벗어난 비율 |
| (e) 설계 불일치 | ProductDesign 의 투입 종류·비율·공정과 실제 계보 비교 |
| (f) 과거 확정 이력 | 같은 불량 유형에서 같은 노드(또는 같은 ItemType) 가 원인으로 확정된 횟수 × 확신도 |

- 분석 기간은 불량 LOT 생성 시각 ±30일, 설비/공정 노드의 정방향 범위는 ±7일 (설정 `cause_scoring`).
- 조건 노드는 이 불량의 추적 경로에서 실제로 이탈했을 때만 (b) 를 계산합니다 (다른 시점 이탈과의 우연한 연관 방지).
- 판정 저장 시점의 후보 순위를 스냅샷으로 저장해 정확도(Top-k) 지표의 기준으로 씁니다.

## ARIMA 주의 부품

- 특성별 시계열(서브그룹이면 평균)에 ARIMA 적합. ADF 로 d 후보를 좁히고 p,q ≤ 3 격자에서 AIC 최소 모형 선택.
- 포인트가 30개(설정) 미만이면 "데이터 부족", 적합이 모두 실패하면 "적합 실패"로 기록하고 배치는 계속 진행.
- 위험 점수 = 향후 h(기본 10) 스텝 중 예측분포가 관리한계·규격 중 안쪽 경계를 넘을 확률의 최댓값.
- 매일 02시(설정) 배치 + 대시보드 "지금 예측 실행". 화면에 "통계적 예측이며 확정 판단이 아님"을 표시.

## 로컬 LLM 어시스턴트

- 모든 화면 오른쪽 위 **어시스턴트** 버튼으로 여는 사이드 패널. 한국어 질문 → 한국어 답변.
- LLM 은 DB 를 직접 보지 않고 고정 도구만 호출: `get_lot`, `trace_upstream`, `trace_downstream`, `get_root_cause_candidates`,
  `get_spc_violations`, `get_watchlist`, `search_defect_history`. 모델이 tool calling 을 지원하지 않으면 JSON 응답 방식으로 자동 대체.
- 답변의 LOT 번호·위반 #·판정 # 는 해당 화면 링크. "도구 호출 N건"을 펼치면 호출 인자와 결과 원문을 볼 수 있습니다.
- 시스템 프롬프트: 데이터에 없으면 "데이터에 없음", 원인은 후보로만, 예측은 확정 아님을 명시.
- Ollama 주소는 루프백/사설망만 허용(외부 주소면 거부). Ollama 가 꺼져 있어도 다른 기능은 정상, 채팅 패널에만 안내.
- 설정 `[llm]`: `ollama_url`, `model`, `temperature`, `num_ctx`, `timeout_seconds`. 특정 모델에 의존하지 않으며,
  개발 PC 에서는 `gemma4:26b` 로 실제 질의를 확인했습니다(CPU 환경에서 답변에 2~3분).

## 데이터 입력

- **업로드 화면**: CSV/Excel → 대상 선택(LOT, 계보, 공정 처리+작업 조건, 측정값, 불량 판정) → 파일 열을 시스템 필드로 **끌어다 놓아** 매핑(또는 선택) → 미리보기·검증 → 검증 통과 행만 적재. 오류 행만 CSV 로 내려받기. 매핑은 템플릿으로 저장해 현장 양식마다 재사용.
- 검증: 필수값 누락, 숫자·날짜 형식, 존재하지 않는 LOT/부품 종류/공정/설비/특성 참조, 중복, **순환 계보**(파일 안 + 기존 DB 계보).
- 작업 조건값은 `cond:<조건 항목 이름>` 필드로 매핑해 공정 처리와 함께 적재.
- **REST 수집 API** (MES/LIMS 연동): `POST /api/ingest/{lots|edges|runs|measurements|defects}` 에 `{"rows": [...], "dry_run": false}`. 업로드와 같은 검증 로직, 오류 행은 응답에 행 번호와 사유로.

## 정확도 지표

판정 저장 시점의 원인 후보 순위를 스냅샷으로 저장하고, 나중에 확정된 원인이 그 순위의 Top-1/3/5 안에 있었는지를
기간별·누적으로 보여줍니다(정확도 지표 화면, 대시보드 카드). 합성 시나리오(`seed-sample`)는 판정·확정 이력을 시간순으로 재현해,
새 원인의 첫 불량들은 순위가 낮다가 판정·확정이 쌓이면 1위로 올라오는 추이를 확인할 수 있습니다.

| 공정 | 용해(용해로-1) → 다이캐스팅(다이캐스팅기-1) → 취출·검사(금형 캐비티-1/2) |

| Machine_Status=1 (가생산·예열) | 조건 "설비 상태(가생산)" 이탈 |
| Nelson 감시 변수 5개 + 용해로 온도 | 측정 특성, **런(용탕 LOT)별 기준선**, R1·R2·R5·R6 (양자화된 변수라 R3·R4·R7·R8 끔) |
| 캐비티별 결함 13종 | 불량 유형 13개, 캐비티 제품 LOT 판정 1,144건 (캐비티 1 17.0% / 2 7.8%, 보고서 수치와 동일) |

시각 정보가 원본에 없어 런마다 가상 생산일(2026-03-02부터 하루씩) 08:00 + 누적 Cycle_Time(정지 상한 600초)을 씁니다.
런이 하루 단위이므로 임포트 시 설비/공정 영향 범위를 ±1일(`cause_scoring.downstream_window_days`)로 설정합니다.

KAMP 프로젝트에서 가져와 범용 기능으로 만든 기법:

- **체제(상위 LOT)별 기준선**: 특성의 기준선 범위를 `상위 LOT별`로 두면 런·배치·용탕마다 따로 관리한계를 계산하고 룰도 체제 안에서만 판정합니다. 런마다 공정 수준이 달라 전역 한계로는 수준 차이가 전부 위반으로 잡히는 문제를 막습니다.
- **안정 운전 창 → 조건 이탈 요소(d)**, **가생산 상태 → 조건 이탈**, **캐비티 → 설비 노드**(캐비티 간 불량률 차이가 (b) 로 드러남).
- 원인 점수 보정(실데이터에서 드러난 문제): 비교군이 없는 Lift 는 중립, 완제품 90% 이상이 거치는 *공통 경로* 노드는 점수를 비례 감쇠, 설비·공정의 SPC 근거는 이 불량의 경로상 LOT 로 한정.

실데이터에서 원인 후보는 안정 운전 창을 벗어난 조건(사이클 시간·실린더 압력·비스킷 두께)이 Lift 최대로 상위에 오르며,
이는 KAMP 분석의 결론(창 밖 shot 의 불량률 상승)과 일치합니다. 단일 설비 라인이라 다이캐스팅기는 비교 대상이 없어
shot 자체의 이탈 근거를 공유한 후보로 표시됩니다(점수 상세에 근거 표시).

실데이터 테스트: `BIF_KAMP_RAW_DIR=<경로> pytest tests/integration/test_kamp_import.py` (경로가 없으면 건너뜀, 형식 호환 합성 픽스처 테스트는 항상 실행).

## 집계 공정 기록 + 자동 요인 분석 (사출기 3호 예제)

`samples/injection_m3/` 의 사출기 3호 낮 조 기록(가상 자료, 1시간에 한 줄)처럼 **LOT 단위가 아닌 집계 기록**도 가져와
시스템이 스스로 불량 원인을 판단합니다. 열 역할은 `mapping.json` 에만 정의하므로 다른 양식도 매핑만 바꾸면 됩니다.

```powershell
cd backend
.venv\Scripts\python -m app.cli seed-process-log --reset --file ..\samples\injection_m3\hourly_2026-03-04_06.csv --mapping ..\samples\injection_m3\mapping.json
```

가져오기: 한 시간 = 생산 실적(LOT) 1건(수량 = 생산 수), 성형 실적(작업자, 성형 조건값), 불량 등록(불량 **수량** + 최다 유형), 정지 행 = 설비 이벤트.

**요인 분석 엔진** (`app/core/causes/drivers.py`, 화면 "불량 요인 분석"): 구조가 다른 데이터(KAMP LOT 단위, 합성 시나리오)에도 같은 절차로 동작합니다.

1. 요인별 준이항 로지스틱 회귀(과산포 보정) → 2. 전진 선택(AIC + 유의성 + 실질 설명력) →
3. **교란 판정**: 주요인 값이 같은 층에서 관측/예상 비로 비교해 차이가 없으면 "다른 요인으로 설명됨" →
4. 불량률을 가르는 경계 학습 → 5. 변화 시작 시점 vs 작업자 교체 시점, 설비 이벤트 전후 비교 →
6. 최다 불량 유형과 요인 연관(약한 근거) → 7. 결론·확신도·권고·데이터 주의사항

사출기 3호 기록에서 시스템이 내린 판단 (테스트로 고정):

| 항목 | 판단 |
|---|---|
| 주요 원인 후보 | **금형 온도**(측정값): 약 58℃ 이상 불량률 9.0%, 그 밖 1.5%, 확신도 높음 |
| 작업자(신입) | 다른 요인으로 설명됨: 같은 금형 온도에서 기술자 10.3% vs 신입 10.2% |
| 사출 압력 80, 냉각 16초 | 다른 요인으로 설명됨 (금형 온도와 함께 움직인 결과) |
| 시간 순서 | 금형 온도 상승은 03-04 13:00 부터 — 신입 투입(03-05) **이전** |
| 03-06 09:00 정지 | 전후 불량률 9.7% → 1.0%, 금형 온도 65 → 51℃. 조치 기록 없음 → 확인 권고 |
| 보조 요인 | 수지 온도 낮음(224~226℃) ↔ 미성형 |
| 학습 경계 | 금형 온도 ≤ 57℃, 수지 온도 ≥ 229℃ (현장 허용 범위가 없는 항목에만 기록, 감사 로그) |

학습 경계는 원인 후보 점수의 "작업 조건 이탈"과 이력 추적 그래프에 "학습 범위"로 반영되어, 금형 온도가 높았던
시간의 원인 1순위가 금형 온도로 나옵니다. 매일 배치로 설비별 분석·학습 경계 갱신이 돌고, 어시스턴트 도구
`get_process_drivers` 로도 물어볼 수 있습니다("사출기 3호 불량이 왜 늘었어? 신입 탓이야?").

## 불량 의심 → 실무자 판단 → 불량 적재

실시간 수집(또는 검사 설비)이 걸러 낸 것은 바로 불량이 되지 않고 **불량 의심**으로 쌓입니다. 메뉴 **3 불량 판정** 화면에서 탭(판정 대기 · 불량 확정(적재됨) · 불량 아님 · 전체)으로 나눠 보고, 공정 단계별로 모아 판정합니다.

| 출처 | 발생 단계 | 의미 | 확정할 때 |
|---|---|---|---|
| 조건 이탈 | 그 조건의 공정 (예: 사출 금형 온도, 원료 건조 수분) | 허용·학습 범위 밖에서 생산 → 그 시간 생산분 재검 필요 | 재검 결과 불량 수량 입력 |
| 관리도 위반 | 그 특성의 공정 | 넬슨룰 신호 | 재검 결과 불량 수량 입력 |
| 검사 불합격 | 외관(비전) 검사 | 검사기가 걸러 낸 수량 (과검출 포함) | 수량 그대로 또는 수정 |

실무자가 **불량 확정**하면 불량 판정(불량 수량 포함)으로 적재되어 요인 분석·원인 추적·정확도·생산 대시보드에 반영되고,
**불량 아님**(재검 결과 양품, 센서 오류, 과검출 등)은 사유와 함께 기록됩니다. 여러 건 일괄 처리도 됩니다. 모든 판단은 감사 로그에 남습니다.

- **4 불량 데이터** (`/defect-data`): 적재된 불량 판정 전체(판정 경로 = 발견 단계·출처, 또는 이력·직접 등록)를 기간·유형·번호로 걸러 보고 CSV(`/api/defects/export.csv`, Excel 호환)로 내려받습니다.
- 요인 분석은 **판정 대기 중인 기록을 뺍니다** (아직 불량 수가 확정되지 않았으므로 0 으로 세지 않음). 화면 주의 문구에 뺀 건수가 표시됩니다.

## 전체 공정 3D · 실시간 DB

매핑의 `line` 에 공정 흐름(원료 건조 → 사출 → 취출·냉각 → 외관 검사 → 포장·출하, 설비·조건·시간·검사 검출률)을 정의하면
마스터에 등록되고, 실시간 수집이 한 기록마다 전 단계를 처리합니다. 3D 디지털 트윈은 트레이가 각 설비를 차례로 지나가고,
의심이 있으면 **검토 대기** 구역으로, 실무자가 판단하면 불량 적재 또는 출하로 이동합니다. 오른쪽 **실시간 DB 적재** 패널에
쓰이는 행(생산 실적, 공정 처리, 조건값, 불량 의심)이 들어오는 대로 표시됩니다.

## 시연 기능: 실시간 수집 · 3D 디지털 트윈

- **실시간 수집 속도**: 기록은 실제 시계(지금 시각) 기준으로 쌓입니다. 배속을 고릅니다 — 실시간(1시간 구간이 1시간 뒤 1건), 10배, 60배(1분 = 1시간, 기본),
  360배(10초 = 1시간), 3600배(1초 = 1시간). 구간 중에는 3초마다 센서 값·진행 수량이 스트림(`progress`)으로 오고(진행 막대, 3D 샷 이동, 실시간 DB 의 sensor 행),
  DB 에는 구간이 끝날 때 1건으로 집계 적재됩니다.
- **실시간 수집** (대시보드 상단): 설비 기록이 실시간 DB로 계속 들어오는 상황을 시연합니다. 자동으로 불량을 만들지 않고 '불량 의심'만 쌓습니다. 기존 기록에서 배운 정상 분포·학습 경계·
  구간별 불량률로 새 기록을 만들고, 주요인(사출기 3호는 금형 온도)이 서서히 범위를 벗어나 → 넬슨룰 경보(R3 연속 상승이 경계 이탈보다 먼저) →
  불량 증가 → 정비 정지 → 회복을 반복합니다. 기록은 일반 적재와 같은 테이블에 쌓이고 SPC 를 즉시 다시 판정합니다.
  화면은 SSE(`/api/live/stream`)로 받아 대시보드·관리도·목록이 자동 갱신됩니다. 실제 RTDB/MES 연동 시에는 수집 API 로 들어오는 데이터에 같은 알림을 붙이면 됩니다.
- **3D 디지털 트윈** (`/simulation`): 공정 순서대로 설비를 배치(마스터의 X/Y/Z 좌표 우선)하고 이벤트 API 를 재생합니다.
  기록 재생(재생·일시정지·속도·시점 이동)과 실시간 모드(들어오는 기록을 즉시 반영)를 지원합니다. 설비 위에 조건값,
  이상(붉게 깜빡임)·정지(주황), 생산 트레이가 출하/불량 구역으로 이동(불량률 색). three.js 는 빌드에 포함되어 오프라인 동작합니다.

## 실무 편의

- **볼 넬슨룰 체크박스** (관리도): 실무자가 R1~R8 을 켜고 끄며 볼 위반만 남깁니다(이 브라우저에 기억). 관리자가 특성에서 끈 룰은 회색.
- **도움말 팝오버**: `?` 에 마우스를 올리거나 Tab 으로 포커스하면 넬슨룰 각 번호, 관리한계, 원인 점수, Lift, 교란, 학습 범위, 확신도 등을 쉬운 말로 설명합니다.
- **LOT 메모 · 검색**: 상단 검색창에서 LOT 번호나 메모 내용으로 찾고, **메모 모아보기**(`/notes`) 화면에서 메모가 달린 제품만 최근 메모 순 카드로 모아 보고(메모 내용 검색, 바로 메모 추가), `LOT 목록` 에서도 메모 있는 것만 걸러 봅니다.
  메모는 실무자 이상 작성, 본인·관리자 삭제, 감사 로그 기록. 이력 추적의 LOT 노드와 불량 등록 화면에서도 바로 씁니다.
